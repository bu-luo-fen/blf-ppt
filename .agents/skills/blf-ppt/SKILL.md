# BLF_PPT

以中文沟通为主。将不完整的想法、论文、项目材料或现有 PPT 转成有依据的汇报；用户无需先填写表单或大纲。新制和实质改版默认按以下阶段推进，没有快速出稿模式。仅检查或局部修复旧 PPT 时执行相关检查与修复，不强行套用无关的制作阶段。

## 阶段 0：收集输入

核对本次汇报所需的论文或项目材料。新制 PPT 和实质性改版必须取得用户提供的参考 PPT；未上传时主动请求上传并结束本轮等待，不得使用默认模板替代。缺少其他必要材料时也请求补齐并等待，不编造内容。材料齐全后进入分析，已解决的问题不重复询问。仅检查或局部修复旧 PPT 的例外见上文。

## 阶段 1：论文分析与内容规划

### 1A：需求澄清

材料齐全后先读论文或项目材料及参考 PPT，初步了解研究内容与任务背景，再判断是否理解用户的真实汇报目的。内部核对：汇报是为了理解论文、展示成果、讲解算法、准备复现还是讨论问题；受众已有知识与所需深度；时间、页数约束或是否允许提出建议；希望重点讲解与压缩的内容；其他会改变结构或表达的特殊要求。这些不是让用户逐项填写的表单。

若仍有影响故事线、技术深度或内容分配的关键未知信息，每轮只问一个最重要的问题，简洁具体，可给少量选项并允许自由回答；问后必须结束本轮等待。根据回答再决定是否追问，不预设固定问卷，不重复询问已明确事项。用户表示没有偏好或授权自主决定某项参数时，记录授权并停止追问该项；普通制作细节自主处理。不得用默认假设代替澄清，也不得在关键需求尚未明确时输出完整页数、章节和逐页方案，或一边追问一边实质性定稿。

### 1B：内容方案与批准

可规划的条件是：主要目标已明确；已了解足够的受众背景；时间与篇幅约束已知或获准提出建议；内容侧重与技术深度已知或获准自主判断；重要特殊要求已识别，若无则不追问。无需声称或计算主观把握百分比。

达到条件后，自主分析研究问题、核心方法、创新点、实验结果、结论、局限及关键图表；区分文献方法、项目已完成成果和计划工作，不编造结果、指标或引用，对证据不足的结论显式标注不确定性。提交论文分析摘要与完整内容方案，写明汇报目标、推荐时长、推荐页数及理由、故事线和章节、逐页核心结论、讲解内容与证据、关键原图和技术难点，以及重要内容取舍的理由。区分用户已确定的要求、Agent 的专业建议与尚待用户决定的实质问题，不把建议写成用户决定。

**关口：**展示完整内容方案后再次结束本轮，等待用户明确批准当前版本和范围。澄清阶段的局部回答不是整体方案批准。用户提出修改时先修订，再等待修订版获批；未经批准不得进入正式素材与视觉规划，更不得组装最终 PPT。

## 阶段 2：素材规划与视觉方案

内容方案获批后，按 **汇报内容及证据需求 → 素材选择与图片规划 → 视觉设计与页面组合** 的顺序工作。逐页为每个重要视觉主体标注类型和选择理由，并据此确定实际制作方式：

- **P 原始证据：**论文原图、真实实验或仿真截图、实际数据图表；保真使用并记来源，不为统一风格生成替代证据。
- **G 生图：**复杂方法框架、系统架构、机制解释、概念或场景示意等解释性主体；默认优先评估整体生图效果。
- **N 原生对象：**标题、正文、页眉页脚、页码、引用、简单流程与模块关系，以及需要准确编辑的表格和数据表达。
- **H 混合：**图片承担复杂视觉主体，原生对象承担生成前已规划好的独立文字层或其他确需编辑的元素。

复杂视觉主体的表达质量和视觉一致性优先于可编辑性；没有可用真实原图且生图能改善表达时，优先选 G 或 H，不得仅因形状方便编辑便默认用 N 重建复杂方法图、系统图、框架图或多模块流程。H 须先规划图文分层，不把遮挡或覆盖错误文字当常规修复。真实论文图表和实验数据不得由生图模型编造。用户要求全部可编辑或有不可替代的编辑需求时遵守，并说明必要的视觉取舍；不按图片或原生对象的比例机械选择。

再实际检查参考 PPT 的比例、布局、字体层级、配色、留白、标志、页眉页脚、页码、引用和页面类型，围绕已确定的素材制定完整视觉执行方案，不机械逐页复制。交付逐页素材选择、待生图片、页面组合与重点检查项。

**关口：**展示素材与视觉方案后结束本轮，等待用户明确批准当前版本。未获批不得请求路线选择、制作样张或批量组装；用户此前已选的路线可以记录，但不能据此跨过关口。若所有视觉素材均无需生图，说明原因，视觉方案获批后跳过阶段 3。

## 阶段 3：生图路线与代表性样张

视觉方案获批后，只要存在 G 或 H 类生图需求且用户尚未指定路线，就提供不预设优先级的 **A** 当前 Codex 任务中生图并继续制作、**B** 独立 ChatGPT 对话生图并带回文件，解释操作差异，不承诺成本或质量优劣，随后结束本轮等待选择。不得把复杂视觉主体改标 N 来规避询问。用户已明确选择时遵守，不重复询问；路线选择本身不代表内容或视觉方案获批。所选路线不可用时说明限制，等待用户重新选择，不静默切换路线，也不用程序绘图或文字描述冒充生图，不默认引入 API Key、付费服务或 CLI 后备。

- **A：**先确认当前任务的生图工具实际可用并调用。生成样张，检查后放入目标页面，向用户展示实际组合效果，结束本轮等待明确批准；获批后才制作剩余图片。
- **B：**先交付可复制的代表性样张任务说明，写清画幅、视觉目标、必要文字、结构关系、素材要求、禁止项、文件名和返回清单；说明正在等待用户从独立窗口带回图片，随后结束本轮。收到后核对文件、检查样张、放入目标页面并展示实际组合效果，再结束本轮等待明确批准。样张获批后才给剩余图片的任务说明；等必要图片返回并检查合格后才能组装。不得假设能控制另一窗口或跳过外部生图直接交付 PPT。

从已批准的逐页方案中，优先选元素层次、模块关系和视觉重点最复杂且能代表全套风格的生图任务作为第一张样张；不默认选封面、图标或最容易的简单流程。按 **选择复杂样张 → 生成并放入目标页面 → 展示组合效果 → 用户明确批准 → 制作剩余图片** 执行；未批准则根据反馈调整并重新展示确认。样张检查视觉风格、图中文字清晰度、结构正确性及页面组合；内部检查或仅展示样张均不等于批准。

以获批样张统一后续图片的主色与强调色、线条箭头图标边框、字体与标签层级、留白密度和学术表达；参考视觉语言，不复制内容或机械套用布局。确需不同风格时在逐页方案中事先说明并获认可。逐张核对术语、拼写、模块、箭头、清晰度与原材料。关键错误先归因，再按所选路线整图微调或重绘；最多两轮有针对性的重绘，仍有关键问题时停止并与用户商定调整，不默认局部遮字修补。

## 阶段 4：批量制作、组装与整稿审阅

只有内容方案、视觉方案和必要时的代表性样张均获明确批准，且必要素材齐全，才按已批准版本批量制作。统一尺寸、字体、色彩、标题和引用；页眉页脚、标题、页码、引用及固定标志优先用原生 PowerPoint 对象，常改文字尽量可编辑。复杂视觉主体按已批准的 G/H 方案保留图片；保留 P 类原图清晰度、比例及来源。

组装计划中的全部页面后，先做可读取、可预览等基础检查，交付明确标为**草稿**的完整 PPTX，不能以几页样张或预览图代替；有能力时可附整稿缩略图。请用户从故事线、章节顺序、详略与节奏、遗漏重复、受众适配、图文布局和视觉统一性审阅，并判断是否需要目录、章节封面或过渡页、页数和总结结构调整；不机械添加这些页面。按反馈修改草稿，提供更新后的候选稿供检查；结构、页数或视觉方案改变时同步更新受影响规划。每次交付草稿或修订候选稿后结束本轮，等待用户反馈或批准。

**关口：**用户明确批准整稿候选稿后，才进入阶段 5 的正式最终校验；前期内容、视觉或样张批准不能代替整稿批准。用户明确表示无需整稿审阅时记录例外。草稿的基础检查不等于最终质量校验。

## 阶段 5：最终质量检查与交付

基于用户批准的整稿候选稿（明确免审时为完整草稿），正式核对 PPTX 结构、页数、布局、字体和越界对象；先看整稿缩略图的风格、节奏与章节一致性，再放大方法图、系统图、数据图、密集页和小字页。核对科研事实、术语、箭头关系、数据与 P 类素材来源，以及遮挡、截断、占位内容、遗漏素材、可读性和必要对象的可编辑性。能渲染就实际渲染；不能则说明限制并做可行检查。可运行 [scripts/audit_pptx.py](scripts/audit_pptx.py) 辅助结构检查，但它不能证明科学或视觉正确性。校验失败先修复并重新检查；若修复实质改变已批准的整稿，按决策约束重新确认。

硬性验收：PPTX 可打开、页数符合计划、没有已知严重科学错误、没有严重截断遮挡或不可读内容、必需素材未遗漏、来源可追溯、无影响使用的占位符或结构问题。严重问题返工；普通装饰瑕疵可记录。默认交付 PPTX，仅在用户要求或确有价值时增加 PDF 等。报告文件、执行过的检查、修复、遗留问题及未能验证的项目，状态用 **通过 / 有条件通过 / 未通过**；不得把未执行的检查写成通过。

## 决策约束

- 用户修改单项偏好只更新该项；例如“更侧重算法细节”或选择 B 路线，不构成内容方案或视觉方案的整体批准。明确批准仅适用于当时展示的版本与范围；提出修改后须更新受影响方案并等待确认。
- 每个必须由用户决定的关口都要结束当前轮：简短说明已完成阶段、待决定事项及获批后要进入的阶段。不得在同一轮提问后自行假定同意并继续。
- 不影响已批准方案的普通排版细节自主处理。若变更实质影响核心内容、重要证据、页数结构或主要视觉方向，说明原因、影响和建议，等待用户批准；局部变更只重确认受影响范围。已经作出的用户决定必须约束后续执行。
- 多轮制作或跨窗口交接确有需要时，可在 PPT 项目目录维护轻量 `project_brief.md`，只记已确认事实、方案版本、来源和待办；不要把项目私人材料写入本 Skill。
