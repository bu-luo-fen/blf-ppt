# 行为验收场景

以下为后续真实 Codex 任务中的人工用例。文档检查和审计脚本测试不能代替实际 Agent 行为验证。

| 场景 | 输入或用户回复 | 期望观察 |
| --- | --- | --- |
| 缺少指定参考稿 | 提供论文并要求沿用某 PPT，但未上传该 PPT | 请求上传参考稿，结束本轮等待；不自行选择默认模板。 |
| 新制缺少参考稿 | 提供论文并要求新制 PPT，未指定也未上传参考 PPT | 主动请求用户提供参考 PPT 并结束本轮；不使用默认模板。 |
| 论文与参考 PPT | 提供论文、项目材料和参考 PPT 并要求汇报 | 联合分析论文与参考稿的不同页面类型，区分论文成果与项目成果；原图与数据图保真并记录来源；澄清关键需求后提交内容方案等待批准。 |
| 宽泛组会需求 | 已提供论文和参考 PPT，只说“帮我制作一份适合组会汇报的文献 PPT” | 先阅读材料，再提出一个最重要的需求澄清问题；本轮不输出完整逐页方案。 |
| 逐轮回答 | 用户回答首个澄清问题，但仍可能有关键未知信息 | 根据回答判断是否继续追问；每轮最多一个问题，不重复、不展示固定问卷，也不提前定稿。 |
| 授权自主决定 | 用户表示时长、页数没有特别要求，可由 Agent 安排 | 记录授权，不再追问已授权参数；只判断其他关键需求是否仍未知。 |
| 澄清完成 | 目标、受众、约束或建议授权、侧重及特殊要求已足以规划 | 提交完整内容方案，区分用户决定与建议，结束本轮等待整体批准；不进入阶段 2。 |
| 局部偏好跨阶段 | 用户只回复“更侧重算法细节” | 澄清期只更新该项并判断其他关键未知；内容方案审批期则修订方案并等待整体批准，均不视为整体批准。 |
| 内容方案未获批 | 已提交论文摘要与逐页提纲，用户尚未答复 | 停在阶段 1；不进入正式素材与视觉规划，也不组装 PPT。 |
| 只修改单项偏好 | 对内容方案只回复“更侧重算法细节” | 更新受影响的方案并再次等待；不视为整体批准。 |
| 视觉方案关口 | 内容方案获批，已提交逐页素材与视觉方案 | 等待视觉方案明确批准；路线选择或生图不提前进行。 |
| 复杂视觉选择 | 已批准内容方案含多模块方法框架，暂无可用真实原图 | 逐页标注 G/H 等资产类型与理由；优先评估生图整体效果，不仅因可编辑性默认改用原生形状。 |
| 生图路线关口 | 视觉方案含 G/H 类图片且已获批，用户未指定路线 | 明确询问 A/B 并结束本轮；不把复杂主体改标 N 规避询问，也不擅自选择路线。 |
| 生图路线不可用 | 用户选定的路线在当前任务不可用 | 说明实际限制并等待重新选择；不静默换路线，不以程序绘图或文字描述冒充生图。 |
| 指定路线 B | 视觉方案已获批，用户选择独立 ChatGPT 生图 | 只交付代表性样张任务说明并结束本轮；等待外部原始图片返回，不直接交付最终 PPT。 |
| 指定路线 A | 视觉方案已获批，用户选择当前 Codex 生图 | 不重复询问路线；确认工具可用并实际生图，将代表性样张放入目标页展示，等待明确批准后才批量制作。 |
| 样张未获批 | 用户返回样张，Agent 已检查并放入页面展示 | 等待用户明确确认组合效果；不制作剩余图片或批量组装。 |
| 复杂样张优先与风格延续 | 视觉方案同时有复杂系统图、封面和简单图标 | 先选最复杂且代表整体风格的系统图作样张；展示目标页组合并等待批准，未获批不得批量生图；后续图片参考已批准样张的视觉语言。 |
| 原始证据保真 | 论文原图、真实实验截图或数据图与整体视觉风格不同 | 标为 P 并保真使用、记录来源；不为统一风格用生图模型伪造或替换证据。 |
| 已批准核心方案变更 | 用户要求改变核心结论、关键证据或页数结构 | 说明影响，修订受影响方案并等待批准；局部变更不无条件重做所有阶段。 |
| 普通排版调整 | 已获批方案下调整边距、字号或局部对齐 | Agent 自主处理并检查，不请求新的整体批准。 |
| 所有制作关口通过 | 内容、视觉、必要样张均获批，图片已返回并检查 | 组装覆盖全部计划页面的草稿 PPTX，保留原图与来源、适当可编辑对象；先交用户整稿审阅，不直接称为最终稿。 |
| 整稿审阅关口 | 用户收到完整草稿，提出增设目录或章节封面、调整页数与节奏 | 判断并落实获认可的修改，同步受影响规划，重新提供候选稿；未获明确批准不进入最终校验，不机械添加目录或章节封面。 |
| 用户免除整稿审阅 | 用户明确表示无需审阅完整草稿 | 记录例外，再执行正式最终校验；不把沉默或前期批准视为免审。 |
| 最终质量校验 | 用户明确批准整稿候选稿 | 检查结构、整稿缩略图、复杂页细节和科学证据；失败先修复并复查，未执行项目如实报告，不虚称通过。 |
| 无需生图 | 已批准的素材与视觉方案只使用真实原图、图表和原生对象 | 说明原因并跳过路线与样张关口，继续组装。 |
| 检查或修复旧 PPT | 只要求检查或局部修复现有 PPTX | 检查已有内容与结构，双遍视觉检查；不强加新制作的批准阶段。 |
| 普通论文问答 | “这篇论文的贡献是什么？” | 不触发 PPT 制作流程，不询问生图路线。 |

各制作场景还应核对事实与引文、文件可打开性、页数、严重排版问题及未执行检查的准确说明。
